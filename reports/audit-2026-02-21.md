# cbspy Codebase Audit

**Date:** 2026-02-21
**Scope:** Code quality, CI/CD, Python standards, dependency utilisation, and enhancement opportunities for data science/economics workflows.

---

## Summary

cbspy is a clean, well-structured library with 99% test coverage and zero lint/type errors. The architecture is sound. However, there are correctness bugs in the data models, missing resource management, unimplemented design-doc promises, and significant gaps in CBS API coverage that limit the library's usefulness. The CI/CD pipeline has a broken Dockerfile and uses outdated publishing practices.

The largest opportunity: cbspy currently exposes only raw dimension codes (e.g. `"GM0363    "`, `"T001038"`) in DataFrames. Every CBS data user must manually fetch dimension endpoints and join labels themselves. Automating this — as `cbsodata` does — would be the single highest-impact improvement.

## Priority 1 — Bugs and Correctness

### 1.1 `dutch_name` is always identical to `name`

| | |
|---|---|
| **File** | `src/cbspy/client.py:118-122` |
| **Why it matters** | The `Column` model advertises bilingual support (`name`, `dutch_name`, `display_name`), but `_parse_column` sets both from the same `"Title"` field. The `display_name` fallback logic is dead code. Tests in `test_models.py` validate a feature that cannot occur in production. |
| **Action** | The CBS API does not serve separate Dutch/English titles in a single response. Two options: **(a)** Remove `dutch_name` and `display_name`, keep only `name`. **(b)** Fetch metadata for both language variants (table ID suffix `eng` vs `ned`) and merge. Option (a) is correct for the current scope. |

### 1.2 `Client` never closes its `httpx.Client`

| | |
|---|---|
| **File** | `src/cbspy/client.py:23-29` |
| **Why it matters** | When no `http_client` is passed, `Client` creates an `httpx.Client()` but never closes it. This leaks connections and file descriptors, and httpx emits `ResourceWarning` on garbage collection. |
| **Action** | Make `Client` a context manager. Track ownership so it only closes clients it created. Add a `close()` method. Update docs to show `with cbspy.Client() as client:` usage. |

### 1.3 Dockerfile references non-existent file

| | |
|---|---|
| **File** | `Dockerfile:21` |
| **Why it matters** | `CMD ["python", "cbspy/foo.py"]` — this file does not exist. The source is at `src/cbspy/`, not `cbspy/`. This is a cookiecutter template leftover. Any `docker build && docker run` fails immediately. |
| **Action** | Remove the Dockerfile entirely (this is a library, not an application) or replace with a useful example (e.g. a container for running the test suite). |

### 1.4 Missing retry logic contradicts design doc

| | |
|---|---|
| **File** | `src/cbspy/_odata.py:64-70` |
| **Why it matters** | The [MVP design doc](docs/plans/2026-02-20-cbspy-mvp-design.md) states: *"Rate limiting / 5xx: Retry once with backoff, then raise `APIError`."* The implementation has zero retry logic. Transient 5xx errors, timeouts, and connection resets all raise immediately. The CBS API occasionally returns 503s under load. |
| **Action** | Add retry-on-5xx with exponential backoff (1 retry, ~1s delay). Handle `httpx.RequestError` and `httpx.TimeoutException`. Make max retries configurable on `Client`. No need for `tenacity` — a simple loop suffices for one retry. |

## Priority 2 — High-Value Data Science Enhancements

### 2.1 Filtering on any dimension, not just periods

| | |
|---|---|
| **File** | `src/cbspy/client.py:76-95` |
| **Why it matters** | `get_data()` only accepts a `periods` filter. Data scientists routinely need to filter by region (`RegioS eq 'GM0363'`), gender, age group, etc. Without server-side filtering, users must download entire tables (potentially millions of rows) and filter client-side. |
| **Action** | Add a `filters: dict[str, list[str]] | str | None` parameter. Accept either a raw OData `$filter` string or a dict like `{"RegioS": ["GM0363", "GM0599"], "Perioden": ["2023JJ00"]}` that gets compiled to OData syntax. |

### 2.2 Column selection (`$select`)

| | |
|---|---|
| **Why it matters** | Many CBS tables have 50+ topic columns. A population researcher may only need 3. Without `$select`, the full payload is transferred and parsed. For large tables this wastes bandwidth and memory. |
| **Action** | Add a `columns: list[str] | None` parameter to `get_data()`. Map human-readable names back to CBS keys, then pass as `$select`. |

### 2.3 Switch from ODataApi to ODataFeed

| | |
|---|---|
| **File** | `src/cbspy/_odata.py:9` |
| **Why it matters** | cbspy uses `/ODataApi/odata/` which returns max 10,000 rows per page. CBS also provides `/ODataFeed/OData/` with no page-size limit — same endpoints, same params, fewer round-trips. For a 500K-row table, ODataApi requires 50+ HTTP requests; ODataFeed may need 1-5. `cbsodata` uses ODataFeed by default. |
| **Action** | Change `_ODATA_API = "/ODataFeed/OData"`. This is a one-line change with large performance impact. Add an option to fall back to ODataApi if needed. |

### 2.4 `UntypedDataSet` support

| | |
|---|---|
| **Why it matters** | `TypedDataSet` replaces CBS statistical symbols with `null`, losing information about *why* data is missing (`.` = not applicable, `x` = suppressed, `-` = nil). Economists doing data quality analysis or imputation need these symbols. |
| **Action** | Add `typed: bool = True` parameter to `get_data()`. When `False`, fetch `UntypedDataSet` and return string columns preserving symbols. |

### 2.5 Period decoder missing half-yearly format

| | |
|---|---|
| **File** | `src/cbspy/_periods.py:18-20` |
| **Why it matters** | CBS uses `2023HJ01` / `2023HJ02` for half-yearly data. The decoder doesn't handle this, silently returning the raw string. |
| **Action** | Add `_HALFYEARLY = re.compile(r"^(\d{4})HJ0([12])$")` mapping to `"2023 H1"`, `"2023 H2"`. Add test cases. |

## Priority 3 — CI/CD and Packaging

### 3.1 Release workflow uses PyPI token instead of trusted publishing

| | |
|---|---|
| **File** | `.github/workflows/on-release-main.yml:51-53` |
| **Why it matters** | Token-based PyPI authentication is deprecated in favour of OIDC trusted publishing. Tokens can leak, must be rotated, and grant broad access. OIDC is scoped, keyless, and the PyPI-recommended approach. |
| **Action** | Configure trusted publishing on PyPI for this GitHub repo. Replace `uv publish` + `UV_PUBLISH_TOKEN` with `pypa/gh-action-pypi-publish@release/v1`. Remove the secret. |

### 3.2 Version management via `sed` is fragile

| | |
|---|---|
| **File** | `.github/workflows/on-release-main.yml:19-24` |
| **Why it matters** | The release workflow uses `sed` to rewrite `pyproject.toml` version, uploads it as an artifact, downloads it in the next job. This is brittle (breaks if formatting changes), adds two extra jobs, and means the version in the repo never matches the released version. |
| **Action** | Use `hatch-vcs` for dynamic versioning from git tags. Add to `pyproject.toml`: `[tool.hatch.version] source = "vcs"`. Remove the `set-version` job entirely. Git tags become the single source of truth. |

### 3.3 No dependency update automation

| | |
|---|---|
| **Why it matters** | No Dependabot or Renovate configuration. GitHub Actions versions, Python packages, and pre-commit hooks will drift. Security vulnerabilities in dependencies won't be flagged. |
| **Action** | Add `.github/dependabot.yml` covering `pip`, `github-actions`, and optionally pre-commit hook ecosystems. |

### 3.4 Ruff version mismatch between pre-commit and dev deps

| | |
|---|---|
| **Files** | `.pre-commit-config.yaml:18` pins `v0.14.14`; `pyproject.toml:38` specifies `ruff>=0.14.14` |
| **Why it matters** | Local `uv run ruff` may use a newer ruff than pre-commit, causing inconsistent lint results between `make check` and `git commit`. |
| **Action** | Pin exact version in `pyproject.toml` (`ruff==0.14.14`) or manage both through Dependabot to keep them in sync. |

### 3.5 Makefile uses `pyproject-build` and `twine` instead of `uv`

| | |
|---|---|
| **File** | `Makefile:24,34` |
| **Why it matters** | The `build` target uses `uvx --from build pyproject-build --installer uv` and `publish` uses `uvx twine upload`. The CI workflow already uses `uv build` and `uv publish`. This inconsistency is confusing and adds unnecessary dependencies. |
| **Action** | Replace with `uv build` and `uv publish` in the Makefile to match CI. |

### 3.6 tox duplicates CI matrix

| | |
|---|---|
| **File** | `tox.ini` |
| **Why it matters** | `tox.ini` defines the same Python 3.10–3.14 matrix that CI already tests. It adds `tox-uv` as a dev dependency and includes `ty check` redundantly. Its value is local multi-version testing, but this is rarely used in practice. |
| **Action** | Either remove `tox.ini` and `tox-uv` from dev deps, or document clearly when contributors should use it vs relying on CI. |

## Priority 4 — Code Quality and Testing

### 4.1 DataFrame construction is row-oriented

| | |
|---|---|
| **File** | `src/cbspy/client.py:101-113` |
| **Why it matters** | Building a `list[dict]` then calling `pl.DataFrame(renamed_rows)` forces Polars to infer schema row-by-row. For large datasets (100K+ rows), column-oriented construction is significantly faster and more memory-efficient. |
| **Action** | Restructure to build `dict[str, list]` (column-oriented). Decode periods as a vectorised Polars operation after construction rather than per-row in Python. |

### 4.2 Unused `conftest.py` fixture

| | |
|---|---|
| **File** | `tests/conftest.py` |
| **Why it matters** | The `http_client` fixture is never used by any test. All tests create their own `httpx.Client()` inline. Dead code in test infrastructure is confusing. |
| **Action** | Remove the fixture. If a shared client is needed later, add it back with proper cleanup (`yield` + `client.close()`). |

### 4.3 Missing edge-case tests

| | |
|---|---|
| **Why it matters** | No tests for: network errors (`httpx.RequestError`), timeouts, malformed JSON responses, empty `DataProperties`, invalid period codes (e.g. `"2023MM99"`), column names with special characters, or multi-page pagination beyond 2 pages. Coverage is 99% by line but many failure modes are untested. |
| **Action** | Add parametrised tests for error conditions. Consider property-based testing with `hypothesis` for the period decoder. Add a timeout test using `respx` side effects. |

### 4.4 `dict[str, Any]` return types from OData layer

| | |
|---|---|
| **File** | `src/cbspy/_odata.py:20,41` |
| **Why it matters** | `get_json()` and `get_catalog()` return `list[dict[str, Any]]`. Callers must know the CBS API schema by convention. TypedDicts would provide autocompletion and static analysis. |
| **Action** | Define `TypedDict` classes for the known CBS response shapes (`CBSDataProperty`, `CBSTableInfo`, `CBSCatalogEntry`). Use these as return types from the OData layer. |

### 4.5 OData pagination assumes absolute nextLink URLs

| | |
|---|---|
| **File** | `src/cbspy/_odata.py:29-38` |
| **Why it matters** | After the first page, `request_params` is cleared and `url` is set to `odata.nextLink`. This is correct for the CBS v3 API (which returns absolute URLs), but the assumption is implicit and would break silently if CBS behaviour changed. |
| **Action** | Add a debug-level log or assertion that `odata.nextLink` is absolute. Low priority but improves robustness. |

## Priority 5 — Future Enhancements

### 5.1 Async support

| | |
|---|---|
| **Why it matters** | httpx natively supports async. Data pipelines and web applications benefit from non-blocking I/O, especially when fetching multiple tables or large paginated datasets. |
| **Action** | Add `AsyncClient` that mirrors `Client` but uses `httpx.AsyncClient`. The OData layer can be made generic over sync/async with minimal duplication. |

### 5.2 OData v4 API support

| | |
|---|---|
| **Why it matters** | CBS has a production v4 API at `datasets.cbs.nl/odata/v1/CBS/` with richer metadata, `in` operator for filters, per-observation statistical symbols, and better dimension hierarchies. CBS will eventually sunset v3. The v4 data model is fundamentally different (cell-oriented `Observations` vs record-oriented `TypedDataSet`). |
| **Action** | Design a v4 backend behind the same `Client` interface. This is a significant effort — the data model pivot from wide to long format requires different DataFrame construction logic. Consider as a v2.0 feature. |

### 5.3 Pandas export option

| | |
|---|---|
| **Why it matters** | Many economists and data scientists still use pandas. While Polars DataFrames can be converted with `.to_pandas()`, offering a `format="pandas"` option or a `.to_pandas()` convenience on the client would lower the barrier to adoption. |
| **Action** | Consider adding `output_format: Literal["polars", "pandas"] = "polars"` to `get_data()`, or document the `.to_pandas()` conversion prominently. |

### 5.4 Caching layer

| | |
|---|---|
| **Why it matters** | CBS metadata rarely changes. Fetching `DataProperties` and dimension endpoints on every `get_data()` call is wasteful, especially when resolving labels. A TTL cache would reduce API calls and improve latency. |
| **Action** | Add optional in-memory caching for metadata responses (e.g. `functools.lru_cache` or a TTL dict). Make it configurable. |

### 5.5 Alternative CBS catalogs

| | |
|---|---|
| **Why it matters** | CBS hosts multiple data catalogs beyond the main one: `dataderden.cbs.nl` for third-party data, and the v4 API has `CBS-Maatwerk` for custom publications. The current client is hardcoded to `opendata.cbs.nl`. |
| **Action** | The `base_url` parameter already supports this in principle. Document how to use alternative catalogs. Consider adding named presets. |
